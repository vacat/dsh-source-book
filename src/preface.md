# 前言

## 为什么要再写一本"只讲 dsh"的书

如果你读过《Agent 技术实战》（agent-book），你已经知道：**所有 Agent 都是同一个
"思考—行动—观察"循环，差别只在每一步投入多少工程保险**。你在那里看到了
pi（可读）、dsh（可扩展）、codex（可生产）三个实现。

但 dsh 在三个库里的定位很特别：**它用"一切皆插件"换取无与伦比的扩展性，用
"事件溯源会话"换取无与伦比的可追溯性。** 这两个特点，恰恰是三言两语讲不透、
值得单独花一整本书去啃的。本书就是把镜头对准 dsh 一家，把它的工程机制
一层层剥开。

读完本书，你会得到三样东西：

1. **一张完整的 dsh 架构地图**：几十个包、几十个 `ctx.*` 服务、几百个事件，
   它们如何拼成一个可运行的 Agent；
2. **一把读复杂代码的钥匙**：dsh 的代码密度很高，但每个设计都对应一条
   Agent Note 里的决策记录。学会"决策驱动阅读"，再复杂的代码也不怕；
3. **一份可迁移的工程方法论**：事件溯源、能力接缝、注册即副作用、不变量断言……
   这些不只是 dsh 的，而是任何大型 Agent 平台都值得借鉴的。

## 这本书不是入门书

本书是 agent-book 的**进阶姊妹篇**。我们默认你：

- 知道推理循环、工具、会话是什么（否则建议先读 agent-book）；
- 会读 TypeScript；
- 有耐心逐行读代码（第 7、8、9 章是全书精读重点）。

如果你只是想快速了解 dsh，读第 1、4、10 章就够建立全局观；
想真正读懂，请按顺序读完整本书。

## 这本书的素材从哪来

本书的"纲"来自 dsh 仓库自身的文档与决策记录，这是它最宝贵的学习资源：

- `docs/architecture.md` —— 官方架构总览（本书第 1 章的底稿）；
- `docs/cordis-primer.md` —— Cordis 插件框架入门（第 2 章）；
- `docs/subsystems/*.md` —— 每个子系统的服务、事件、API 参考；
- `.agents/notes/implemented/architecture/*.md` —— **Agent Notes**：每一次
  架构决策的"问题—决策—后果"记录，是理解"为什么这样写"的第一手材料；
- `packages/**/src/*.ts` —— 源码本身。

## 阅读约定

- 代码片段标注来源文件；建议边读边在本地仓库对照；
- 每个重要概念尽量给出"Agent Note 出处"，方便你查原文；
